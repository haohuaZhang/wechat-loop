# AGENTS.md —— 从 0 到 1 自主交付协议

> 🖥️ **操作系统强预警**：本协议自举脚本与门禁重度依赖 Bash 环境（`grep/awk/mktemp`）。Windows 用户必须在 **WSL (Ubuntu)** 或 **Git Bash** 终端下运行 Cursor/终端，**严禁**在原生 CMD/PowerShell 中执行自举脚本，否则会直接报错！
> ⚠️ **强制启动红线**：AI 读完本文件后的**第一个动作**，必须是提取并执行“附录 A”的自举脚本。在 `./tools/gate/bootstrap.sh` 成功跑通前，**严禁编写任何业务代码**！
> 优先级：**用户当前明确指令 > `.cursor/rules/` > `.state/PROJECT.md` > `docs/platforms/*` > 本文件通用条款 > 模型默认习惯**。
> 业务专属（平台字段、选择器、账号规则）禁止写进本文件，必须写 `docs/platforms/`。
> 核心目标：用户只描述需求，Agent 按本流程交付一个**安装即可运行、核心流程可用、对标样本保真**的主产物。

## 0.0 一页执行卡（会话首屏，禁止跳过）

| # | 动作 | 通过条件 | 产物 |
|---|---|---|---|
| 0 | 自举 | 没有 `tools/gate/` 就提取并执行附录 A；已有则 `./tools/gate/bootstrap.sh` exit 0 | `tools/gate/` |
| 1 | 开工回声 | 按 §0.1 落盘：需求复述、MVP 三问、7 条默认决策、Skill 装配 | `.state/last-echo.md` |
| 2 | Stage 1 → 2.1 | 每条 P0 有可测 AC，且映射到工作包 | `docs/requirements.md`、`docs/plan/TODO.md` |
| 3 | DESIGN LOOP | 顺序固定：Analyze → Observe → Think → Plan → Deliberate → Design。Freeze 是 Design 的产出 | `docs/design.md` |
| 4 | INNER LOOP | Stage 3 先写会失败的 E2E → Stage 4 编码 → Stage 4.1 自审 → Stage 5 跑绿 → 失败进 Stage 6（≤5 次）→ Stage 7 单测 | `tests/`、`TASKS.md` |
| 5 | SUBMIT LOOP | Lint → Pre-Submit → Stage 8 MR Creation → Stage 9 Code Review（≤5 次）→ Submit | 评审记录、交付包 |
| 6 | OUTER LOOP | Post Submit → Staging → Canary → Production → Measure → Stage 10 → Human Review → Manual Merge | `docs/reports/final.md` |
| 7 | 交付红线 | `install.sh`、`start.sh`、`verify.sh` 可执行；`MOCK=1 bash verify.sh` 和 `./tools/gate/verify-gate.sh --all` exit 0；§0.5 保真 PASS | 三件套 + 证据 |

**会话启动顺序（唯一合法）**：
1. 没有 `tools/gate/` → 只执行附录 A 自举。
2. 读覆盖层（`.cursor/rules/**`、`.state/PROJECT.md`、`docs/platforms/*`）。
3. 写 `.state/last-echo.md`（§0.1）。
4. `./tools/gate/echo-check.sh`（exit 非 0 禁止改业务代码）。
5. `./tools/gate/bootstrap.sh`（必须 exit 0）。
6. 声称「已交付」前，必须先跑通 `MOCK=1 bash verify.sh` 与 `verify-gate.sh --all`。

## 0.2 唯一状态源与循环计数

`TASKS.md` 是任务与进度的唯一状态源，末尾必须维护只追加的 `## Loop Log`。
`state/loop-counter.json` 由脚本自动维护，**AI 禁止手动编辑**：
- `inner_fix` 失败 ≥ 5 → 强制追加 feedback，回退 Design Loop。
- `submit_review` 失败 ≥ 5 → 强制追加 feedback，回退 Inner Loop。
- `outer_verify` 失败 ≥ 3 → 强制追加 feedback，回退 Submit Loop。
- `state/retry-counter.json` 记录同一 AC-ID 失败计数，≥5 次触发停机分析。

> **【重要机制提醒】**：在执行测试或构建命令时，AI 必须通过环境变量告诉脚本当前在哪个 Loop。例如在 Stage 5 跑绿时：`export CURRENT_LOOP=inner_fix && bash tools/gate/generate-run-json.sh`。这能确保脚本的计数与拦截机制正确生效。

## 0.3 自主级别与人类检查点

| 级别 | 行为 | 是否需要人类批准 |
|---|---|---|
| L1 | 本地实现、运行、自测 | 否 |
| L2 | 创建分支、提交、生成 patch | 否（本地） |
| L3 | 部署到预发/测试环境 | 是（首次需确认） |
| L4 | 发布到真实账号、生产环境、付款、删除数据 | **必须** |

**必须停机请求人类的场景**：需要凭证/OAuth授权；需真实发布/群发；根本歧义；不可逆操作；连续修复 5 次失败；发现安全红线。扫码登录/验证码一律 L4，AI 只给指引。

## 0.4 十二条不可协商底线

1. **需求驱动**：只实现 AC 内的功能，不擅自加戏。
2. **无 AC 不写码**：每个 P0 必须有二值可判定的 AC。
3. **测试先行**：Stage 3 必须先写会因“未实现”而失败的 E2E，红灯后方可写实现。
4. **不可破坏**：任何改动后，相关测试与全量冒烟必须通过。
5. **证据完成**：没有命令输出/报告/截图/日志，不得声称完成。
6. **循环有上限**：由 `loop-counter.json` 机械控制，超限自动回退上层 Loop。
7. **禁止伪造**：禁止 skip/xfail/only、删测试、放宽断言、改快照来“变绿”。`gate` 脚本强制扫描。
8. **凭证不入库**：密钥只从环境变量读取，禁止写进提示词。
9. **最简架构**：默认最简架构，未经 ADR 不引入重型设施。
10. **交付即验收**：`gate` 全绿只证明可运行；主产物另过 §0.5 保真才允许说可直接使用。
11. **Skill 不越权**：可执行型 skill 必须先登记；与本文件冲突时以本文件为准；每阶段 ≤ 2 个。
12. **宿主文风不压过交付**：不得因个人偏好取消带 AC-ID 的测试和 README 三行上手。

## 0.5 交付保真度（Reference Parity）

出现下列**任一**即强制启用本条：用户提供样本；需求含“可直接发布”；主产物是内容态（文章/海报/草稿）。

**必须采集**：结构骨架、媒体清单、链接与组件、平台字段、完成定义（落盘 `docs/samples/parity-checklist.md`）。

**二值门禁**（缺一 FAIL）：
- [ ] 结构：必选区块全部出现，顺序一致。
- [ ] 媒体：必选媒体位均有真实资源（禁止灰块占位）。
- [ ] 链接：可点入口在产物中为可解析 URL。
- [ ] 落点：进草稿箱/可发表，必须有真实草稿 ID/URL 或人类确认的等价物。
- [ ] 证据：`docs/evidence/parity.json` 中 `result=PASS`、`missing=[]`。

**FAIL 不得停工**：出现缺口必须进入 Stage 6 修复，禁止写“已交付”或把缺槽改成 N/A。满 5 次或需 L4 凭证才标 `BLOCKED`。

# 第 2 章：Stage 0-2.1 立项与需求拆分

## 2.1 默认决策表（仅作设计参考）
- **本地存储**：单机优先 SQLite / 本地文件。
- **模型/外部服务**：adapter 接口 + 默认 mock。
- **UI/桌面壳**：既有栈优先；绿地 Tauri/Electron。
- **core 边界**：零平台 API。
- **配置/日志**：`.env.example` + 结构化 JSON。

## 2.2 一句话需求转 AC 的 8 步
1. **解剖**：动词、名词、外部能力。
2. **形态**：匹配主类型（Web/API/CLI 等）。
3. **核心流程**：3-7 步端到端路径。
4. **外部依赖**：凭证、付费、降级级别。
5. **拆 AC**：每步 1-3 条，Given/When/Then 二值可测，标注 A/M。
6. **歧义自检**：扫用户、流程、数据、外部依赖。
7. **MVP 三问**：价值闭环、必要性、可独立交付。
8. **冻结**：写入 `requirements.md`。

## 2.3 逻辑拆分
- 按**垂直切片**拆分（能独立演示用户可见结果），禁止按“先写所有模型再写页面”拆分。
- `core/` 禁止 import 任何平台 API（DOM/Node/扩展等），差异落 `adapters/`。
- 多端项目一次只做一个 P0 端，其余端仅留占位，不得多端齐头并进。

# 第 3 章：DESIGN LOOP（设计循环）

**顺序不可调换**：Analyze（风险）→ Observe（探环境、读样本）→ Think（≥2 方案对比）→ Plan（文件树/模型/契约）→ Deliberate（失败模式/安全）→ Design（写文档并 Freeze）。

**GATE-D 通过标准**（缺一不可）：
- [ ] 目标、组件图、接口、数据模型、测试策略等 12 项全部非占位。
- [ ] 契约可解析（API/CLI/库按各自形式）。
- [ ] 至少 2 个方案比较且理由可复核。
- [ ] `core` 零平台 API。
- [ ] 若触发 §0.5，`parity-checklist` 已冻结。

# 第 4 章：INNER LOOP（内层循环：测试先行）

## 4.1 Stage 3：E2E 红灯先行
- 按 P0 AC 1:1 编写，用例名含 `AC-ID`。
- 首次运行必须因“功能未实现”而失败，不能因语法/环境错误失败。
- 每条 P0 包含一正一反两个断言。
- 建立追溯矩阵 `tests/traceability.json`。

## 4.2 Stage 4：编码
- 按 WP 垂直切片实现。
- 契约先行：先有接口签名/schema，再写实现。
- 禁止占位实现（`TODO`、假数据写死）。

## 4.3 Stage 4.1：本地自审
- 评审人不得是该文件作者（单 Agent 需按 checklist 逐条留痕）。
- 检查错误路径、无吞异常、无硬编码密钥、输入校验、无 `console.log` 遗留。

## 4.4 Stage 5-6：运行与失败分析
- 在干净环境执行全量 E2E。
- **强制命令**：每次跑测试，必须执行 `export CURRENT_LOOP=inner_fix && bash tools/gate/generate-run-json.sh`（严禁直接跑测试命令，否则不计入计数器）。
- 失败必须进入 Stage 6，生成 `docs/failure-analysis/{AC-ID}-{date}.md`。
- 归因分类（产品/测试/环境/外部/Flaky），同 AC 最多 5 次，第 3 次必须换假设。

## 4.5 Stage 7：单测与回归
- 补边界、异常、幂等测试。
- 核心模块覆盖率 ≥ 80%。

# 第 5 章：SUBMIT LOOP（提交循环）

- **Lint**：静态检查通过，不用 `any` 掩盖。
- **Pre-Submit**：无密钥、无高危漏洞、无 TODO、追溯矩阵 passed。
- **Stage 8 (MR Creation)**：生成 PR/patch，附验证命令与证据。
- **Stage 9 (Code Review)**：非作者评审，不通过回 Stage 4，最多 5 次。
- **Submit**：`gate` 全绿且评审通过后才允许提交。
- **强制命令**：在最终提交前，必须执行 `export CURRENT_LOOP=submit_review && bash tools/gate/verify-gate.sh` 来验证门禁。

# 第 6 章：OUTER LOOP（交付与人工确认）

- **单机等价实现**：
  - Staging：隔离数据目录启动并跑 smoke。
  - Canary：第二数据目录跑固定样例（写入 `canary.json`，不允许只打印）。
  - Production：交付包就绪，**停在 Human Review**，未经授权不安装。
  - Measure：看最近 3 次 `MOCK=1 bash verify.sh` 记录。
- **Stage 10**：生成 `final.md`（安装/启动/验证/已知限制/回滚）。
- **Human Review**：人类按 README 走通主流程，确认无阻塞后自行 Merge。

# 第 7 章：工程质量与安全基线

## 7.1 UI 与前端
- 一条命令启动，固定端口，带 `.env.example`。
- 四态：加载、空、错误（可重试）、无权限。E2E 必须断言非 ready 态。
- 样式必须真浏览器实测，读 `getComputedStyle`，覆盖 360/768/1440 无横向滚动。
- 无 console error、无资源 404。

## 7.2 后端与外部依赖
- 接口契约与实现一致，入参 schema 校验。
- 幂等：`Idempotency-Key` + 唯一索引。
- 外部平台降级矩阵：L1（全 API）→ L1.5（官方 API+人工确认）→ L2（半自动导出）→ L3（只读采集）→ L4（需绕过风控，直接 BLOCKED）。
- 禁止绕过验证码/风控。

## 7.3 AI 与内容生成
- 提示词封装在 `adapters/llm`。
- 强制结构化输出（JSON Schema），校验敏感词与引用。
- 缺对标样本中的必选媒体/链接时，状态不得超过 `generated`。

## 7.4 AI 编码与运行安全防线（机械守护）
1. **命令 allowlist + DANGEROUS 过滤**：`generate-run-json.sh` 拦截 `; && --force rm -rf curl|sh`。
2. **L4 grep 拦截**：`bootstrap.sh` 扫描 `TASKS.md`，命中注入/prompt injection 直接 exit 99。
3. **SHA256 指纹锁 + 重跑比对**：AI 改了 gate 脚本启动即死；`verify-gate.sh` 重新执行命令比对退出码，硬编码 exit_code=0 无效。
4. **Husky pre-commit**：拦截密钥入库与 skip/only。
5. **配置层防作弊**：`verify-gate.sh` 会扫描 `package.json`、`Makefile`，拦截 `|| true` 或强制 `exit 0`。
6. **网络错误豁免**：因网络波动（如 ETIMEDOUT）导致的失败不占用 Inner Fix 额度，防止网络断连引发系统死锁。

### 7.4.1 MCP 权限策略（可选）
若项目需使用外部 MCP 工具，必须在根目录提供 `.mcp-policy.json`，否则 `bootstrap.sh` 将默认拒绝所有 MCP 调用。示例：
```json
{
  "servers": {
    "github": {
      "allowed": true,
      "filter": ["list_issues", "get_file_contents"],
      "deny": ["push_files", "delete_repository"]
    }
  }
}
```

# 第 8 章：多组件协作（精简版）

- **契约唯一真源**：`contracts/` 只有提供方（如后端）能写，消费方（如前端）只读并评审。
- **契约冻结后方可开工**：未过 G1 契约冻结，只能基于 mock 开发。
- **合并顺序**：`contracts → 提供方 → 消费方`。
- **文件所有权**：同一文件同一时间只有一个 Owner 写入，动笔前在 `TASKS.md` 认领。
- **Handoff 必须包含**：变更摘要、契约 diff、分页/错误码变更、回滚点。未收到 ack 不得开工。
- **阻塞升级**：超过一个工作循环必须升级主 Agent，禁止私造接口。

# 第 9 章：验证与证据

- 所有验证证据由 `tools/gate/generate-run-json.sh` 自动落盘（禁止手写）。
- `run.json` 包含：命令列表、真实退出码、耗时、trace_id、commit SHA。
- `gate` 脚本不相信 `run.json` 的退出码，而是**重跑一遍**比对。
- 交付必须包含 `install.sh`、`start.sh`、`verify.sh`，且 `MOCK=1 bash verify.sh` exit 0。

# 第 10 章：交付门槛与硬检查（缺一即未交付）

## 10.1 Definition of Done（DoD）

**必备**：
- [ ] 干净环境按 README 安装/运行成功。
- [ ] `doctor` / `verify` / `gate` 全绿。
- [ ] P0 A 类 AC 测试通过；M 类有步骤与证据（单人可 Review 签字）。
- [ ] 稳定性：非 UI 连续 3 次，UI 连续 2 次全绿，skip=0。
- [ ] 无密钥入库，无核心路径假实现。
- [ ] `install.sh`、`start.sh`、`verify.sh` 可执行，`MOCK=1 verify` exit 0。
- [ ] 若触发 §0.5，`Parity=PASS` 且证据齐全。

**按适用**：
- [ ] 有 UI：无 console error，无横向滚动，四态齐全。
- [ ] 有数据库：迁移 up/down 通过。
